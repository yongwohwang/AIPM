# 0001. 기술 스택 선정

- **상태:** 미결 (Proposed)
- **날짜:** 2026-07-27

## 배경

AIPM 저장소는 현재 비어 있고, 만들려는 산출물의 형태에 따라 적합한 스택이 갈립니다.
스택을 잘못 고정하면 초기 코드 대부분을 버려야 하므로, 결정 전까지는 스택 중립적인
기반(문서, 저장소 규칙)만 둡니다.

## 선택지

### A. 웹앱 — TypeScript + Next.js

PM이 브라우저에서 쓰는 도구(요구사항 문서 생성, 이슈 보드, 스펙 리뷰 뷰) 중심일 때.

- 장점: UI 개발 속도, 배포 간편(Vercel 등), 프론트/백엔드 단일 언어
- 단점: 무거운 데이터 처리·AI 파이프라인에는 부적합

### B. 백엔드/파이프라인 — Python + FastAPI

이슈 수집·분류, 임베딩·검색, 배치 요약 등 데이터/AI 파이프라인 중심일 때.

- 장점: Claude SDK 및 데이터 생태계와의 궁합, 비동기 API 서버 구성 용이
- 단점: 사용자 UI가 필요하면 별도 프론트엔드를 추가해야 함

### C. CLI 도구 — Python + Typer

개인/팀 워크플로에 붙이는 터미널 도구 중심일 때.

- 장점: 가장 빠른 착수, 배포 부담 없음, 자동화·CI 연동 쉬움
- 단점: 비개발 직군 사용자에게는 진입장벽

## 결정

미정. 아래 질문에 답이 나오면 확정합니다.

1. 주 사용자는 누구인가? (본인 / 개발 팀 / 비개발 PM 조직)
2. 산출물의 형태는? (웹 UI / API 서비스 / 터미널 도구)
3. 기존 도구(Jira, Notion, Slack, GitHub 등)와 연동이 필요한가?
