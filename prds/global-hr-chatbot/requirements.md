# 글로벌 인사관리 챗봇 요구사항 정의서 (v0.2)

Phase 1: 국외근무직원 부임·복귀 안내 + 보수·복지 HR Q&A

## 1. 개요

- **목적**: 국외 주재원의 반복적인 부임·복귀·규정 문의를 챗봇이 1차 응대하여,
  담당자는 검증·예외관리 등 고부가 업무에 집중하도록 한다.
- **배경**: 담당자(권수아 계장 등, 글로벌성장지원부/글로벌추진부)가 동일 문의에
  반복 응대 중이며, 국가별 안내 자료 형식이 불일치하고 담당자 암묵지 의존도가 높음.

## 2. 범위

| 구분 | 내용 |
|---|---|
| **포함** | ① 부임·복귀 절차·체크리스트·FAQ 안내<br>② 보수·복지·HR 규정 Q&A (근거 인용) |
| **제외** | 계약서 검토, 시행문 발송, 국외출장 관리 |
| **파일럿 대상** | 1개국 우선 적용 (제안: 인도네시아, *확정 필요*) |
| **소속유형** | organic(지점)·inorganic(현지법인) 구분 처리 필수 |

## 3. 대상 사용자 (단계적 확대)

| 단계 | 사용자 | 조건 |
|---|---|---|
| **Phase 1** | 글로벌성장지원부·글로벌추진부 **담당자 전용** | 내부 검증·튜닝 목적 |
| **Phase 2** | + **국외점포 주재원** | Phase 1 성능 검증 통과 시 확대 (*통과 기준 확정 필요*) |

## 4. 핵심 요구사항

| ID | 요구사항 | 우선순위 |
|---|---|---|
| R1 | 국가·소속유형 선택 시 맞춤 부임/복귀 체크리스트·필요서류 제공 | P0 |
| R2 | 부임·복귀 절차를 단계별로 안내 | P0 |
| R3 | FAQ는 **룰 기반**으로 우선 자동 응답 | P0 |
| R4 | 룰 매칭 실패 시 **LLM이 규정 문서를 검색(RAG)해 응답 생성** — 자유 생성 금지, 검색된 원문 범위 내에서만 답변 | P0 |
| R5 | 모든 응답(룰/LLM 공통)에 **근거 조항 원문을 미리보기**로 제공 — 해당 조항 위치를 하이라이트하여 문서 내 확인 가능 | P0 |
| R6 | LLM도 근거 문서를 찾지 못하면 답변을 보류하고 담당자 연결 | P0 |
| R7 | 문의 로그 적재 (FAQ 후보 도출, LLM 폴백 발생 빈도 추적용) | P1 |

## 5. 비기능 요구사항

- 룰 우선 → LLM 폴백 구조: LLM은 검색된 규정 원문 밖의 내용을 생성하지 않는다
- 모든 지식 문서에 [국가·소속유형·시행일자] 태깅 → 검색 필터링 근거
- 문서 미리보기는 사내 인증된 사용자에게만 노출 (열람 권한 통제)
- 급여 등 민감 개인정보는 저장하지 않는다

## 6. 성공 지표

| 지표 | 현재 | 목표 | 측정 방법 |
|---|---|---|---|
| 반복 문의 응대 건수 | 미측정 | 파일럿 전 2주 baseline 확보 후 감소율 산정 | 담당자 문의 로그 |
| 챗봇 자가해결률 | - | 에스컬레이션 없이 종료 60%+ | 챗봇 세션 로그 |
| LLM 폴백 오답(오인용) 건수 | - | 담당자 검증 기간 0건 목표 | 담당자 검수 결과 |

## 7. 일정(안)

- Phase 0 (2주): 파일럿국가 확정, 안내서·FAQ 표준양식 정리, baseline 측정 시작
- Phase 1 (3~4주): 담당자 전용 파일럿 구축·검증
- Phase 2: 검증 통과 시 주재원 대상 확대

## 8. 미확정 사항 (Open Questions)

- 파일럿 국가 확정
- Phase 1 → Phase 2 확대 통과 기준 (정답률/오답 건수 등 정량 기준)
- 챗봇 채널 (사내 메신저 / 별도 웹) 및 구축 환경 제약(망분리 여부, 사용 가능 LLM)
