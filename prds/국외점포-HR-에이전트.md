# I. 제품 정의

## 5. 제품명 / Product Name

**국외근무직원 HR 에이전트** (가칭)

## 6. 제품 요약 / Executive Summary

국외근무직원의 **부임·복귀 절차 안내**와 **보수·복지 및 HR 규정 문의 응대**를 담당하는 AI 에이전트다. 사내 AI 플랫폼 위에 구축한다.

현재 국외근무직원 129명(인니 16 · 캄보디아 8 · 국외점포 105)의 문의가 본부 담당자 4~6명에게 집중된다. 같은 질문이 반복되고, 답변이 기록되지 않으며, 규정 해석 노하우가 담당자 개인의 경험에만 존재한다. 특히 **매년 2월 정기인사 시기에 부임·복귀 문의가 폭주하는데 하필 그때 담당자도 교체**되어, 가장 경험이 적은 담당자가 가장 많은 문의를 받는 구조가 반복된다.

본 제품은 규정을 **조항 원문과 소관부서까지** 정확히 찾아주고, 국가·법인격에 맞는 부임·복귀 절차를 안내한다. 1차는 **담당자 전용 내부 도구**로 출시해 답변 품질을 실사용으로 교정한 뒤, **담당자가 확정한 답변만** 국외근무직원에게 공개한다.

핵심 설계는 **답변 책임 등급 분리(L1/L2/L3)** 다. AI는 규정 원문 인용(L1)과 실무 안내(L2)만 답하고, 유권해석(L3)은 답하지 않고 소관부서로 연결한다. 이로써 규정 소관(HR/직원만족부)과 답변 주체(글로벌사업그룹)가 다른 구조적 문제를 해소한다.

### 페르소나 A — 본부 담당자 (주 사용자)

- 글로벌성장지원부 또는 글로벌추진부 소속. 국외 HR 업무를 담당한다.
- 하루에도 여러 건의 문의를 받으며, 그때마다 규정집과 안내 자료를 찾아본다.
- **순환보직으로 1~2년마다 교체된다.** 전임자의 판단 기준을 알 방법이 인수인계 문서와 구두뿐이다.
- 2월 정기인사 시기에는 본인의 업무 인수인계와 부임자 문의 폭주가 동시에 발생한다.

### 왜 담당자를 먼저 대상으로 하는가

국외근무직원 대상 챗봇을 먼저 출시할 경우의 리스크는 기술이 아니라 **채택**이다. 급하면 챗봇 대신 담당자에게 메신저를 보낸다. 더 빠르고 확실하며 책임 소재가 명확하기 때문이다. 부임은 2~3년에 1회 발생하는 이벤트라 재방문이 없어 학습 곡선도 타지 못한다.

사용 빈도로 보아도 담당자가 압도적이다.

| | 예상 사용량 |
|---|---|
| 담당자 6명 (매일 사용) | **주 60~90회** |
| 국외근무직원 129명 (연 3회 가정) | 주 7~8회 |

담당자를 먼저 대상으로 하면 **채택이 보장되고**, **답변 품질을 실사용으로 교정**할 수 있으며, **공개 시점에 이미 검증된 상태**가 된다.

# IV. 제안 솔루션

## 12. 제안 솔루션 / Proposed Solution

사내 AI 플랫폼 위에 **국외 HR 지식베이스 + 대화형 에이전트**를 구축한다.

```
규정·지침 ──(자동 동기화)──┐
부임 안내서 ──(부서 관리)──┼──▶ 지식베이스 ──▶ HR 에이전트 ──▶ 담당자
서류 양식  ──(부서 관리)──┤   (시행일·국가·          │              │
과거 사례  ──(자동 축적)──┘    법인격·소관)          │         🚦 확정
                                                     │              │
                                          L3 판정 → 소관부서 연결   ▼
                                                              공개 (Phase 2)
                                                                   │
                                                        국외근무직원 129명
```

### 핵심 설계 — 답변 책임 등급 (L1 / L2 / L3)

국외근무 지침의 소관은 **HR/직원만족부**이나 실무 답변은 **글로벌사업그룹**이 수행한다. 이 분업 자체는 정상이지만, AI 시스템에 넣으면 **기록이 남고, 129명에게 동시에 전달되며, "부서 공식 견해"로 인식된다.** 지금까지 "담당자의 실무 안내"였던 것이 "부서의 유권해석"처럼 보이게 된다.

모든 답변을 세 등급으로 구분하고 **AI는 L1·L2만 수행한다.**

| 등급 | 유형 | 예시 | 소관 | AI 응답 |
|---|---|---|---|---|
| **L1** | 규정 원문 인용 | "보수·복지 규정 제○조: 주택수당 한도는 ○○" | HR 소관이나 **인용은 해석이 아님** | ✅ 허용 |
| **L2** | 절차·실무 안내 | "부임 전 제출 서류는 ○○이며 양식은 여기 있습니다" | **글로벌 자체 소관** | ✅ 허용 |
| **L3** | 해석·판단 | "배우자가 현지 취업했는데 가족수당 대상인가요?" / "예외 승인 가능한가요?" | **HR 유권해석 필요** | ❌ 차단·연결 |

> **현재 담당자가 하는 답변의 대부분은 이미 L1 + L2다.** 유권해석이 필요한 L3는 현재도 HR에 확인하고 있다.
> 따라서 **AI는 책임 경계를 바꾸지 않는다. 암묵적으로 지켜지던 경계를 명시적으로 만들 뿐이다.**
> 오히려 현재보다 안전하다 — 지금은 담당자가 무심코 L3를 답할 수 있으나, 시스템은 이를 감지해 차단한다.

**부수 효과**: L3 질문의 대부분은 "제 경우에는?" 형태다. 개인정보를 처리하지 않는다는 결정(§22)이 자연스럽게 L3 차단 장치로 작동한다.

## 13. 주요 기능 / Key Features

| # | 기능 | 설명 | 단계 |
|---|---|---|---|
| **F1** | **규정 Q&A** | 자연어 질문에 대해 관련 조항 **원문 + 조항번호 + 소관부서**를 반환. 시행일 기준 현행 규정만 검색 | Phase 1 |
| **F2** | **L3 판정·차단** | 유권해석이 필요한 질문을 감지해 답변하지 않고 소관부서로 연결 | Phase 1 |
| **F3** | **사례 축적** | 담당자가 확정한 답변을 근거 조항과 함께 자동 기록. 과거 처리 건 검색 지원 | Phase 1 |
| **F4** | **답변 교정 루프** | 담당자가 수정·확정한 내용이 지식베이스로 재투입되어 이후 답변에 반영 | Phase 1 |
| **F5** | **부임·복귀 체크리스트** | 국가·법인격·가족 동반 여부에 따른 개인화된 준비 항목과 기한 제공 | Phase 2 |
| **F6** | **서류 양식 제공** | 국가·용도별 최신 서류 양식을 직접 제공 | Phase 2 |
| **F7** | **답변 공개 관리** | 담당자가 확정한 Q&A만 국외근무직원에게 공개 전환 | Phase 2 |
| **F8** | **규정 개정 감지** | 근거 규정 개정 시 관련 확정 답변을 `검토필요`로 표시 | Phase 2 |

## 14. 유스케이스 / Use Cases (Scenarios)

### UC-1. 담당자가 규정 근거를 찾아 회신한다 (Phase 1)

| 단계 | 내용 |
|---|---|
| 상황 | 국외근무직원이 "주택수당 한도가 얼마인지" 문의해 왔다 |
| 1 | 담당자가 에이전트에 질문을 입력한다 |
| 2 | 에이전트가 국가·법인격 조건이 없음을 확인하고 되묻는다 |
| 3 | 담당자가 "인도네시아 자회사"라고 답한다 |
| 4 | 에이전트가 **조항 원문 + 조항번호 + 소관부서(HR/직원만족부) + 면책 문구**를 반환한다 |
| 5 | 담당자가 내용을 확인하고 회신한다. 필요 시 답변을 수정한다 |
| 6 | 확정된 답변이 사례로 자동 기록된다 |
| 결과 | 규정집을 찾는 시간이 사라지고, 근거가 시스템에 남는다 |

### UC-2. 유권해석이 필요한 문의가 차단된다 (Phase 1)

| 단계 | 내용 |
|---|---|
| 상황 | "배우자가 현지에서 취업했는데 가족수당 대상인지" 문의가 왔다 |
| 1 | 담당자가 에이전트에 질문을 입력한다 |
| 2 | 에이전트가 이를 **L3(유권해석 필요)로 판정**한다 |
| 3 | 답변하지 않고 "규정 해석이 필요한 사안이며 소관부서(HR/직원만족부) 확인이 필요합니다"를 안내한다 |
| 4 | 관련 참고 조항은 함께 제시하되 적용 여부는 판단하지 않는다 |
| 5 | L3 차단 이력이 로그에 기록된다 |
| 결과 | 잘못된 유권해석이 시스템에 남지 않는다 |

### UC-3. 부임 예정자가 준비 항목을 스스로 확인한다 (Phase 2)

| 단계 | 내용 |
|---|---|
| 상황 | 2월 인사발령으로 인도네시아 부임이 확정되었다 |
| 1 | 부임 예정자가 국가·법인격·가족 동반 여부를 입력한다 |
| 2 | 개인화된 준비 체크리스트가 생성된다 |
| 3 | 각 항목에 필요 서류 양식이 직접 링크되고, 기한과 남은 일수가 표시된다 |
| 4 | 항목별 규정 근거를 펼쳐볼 수 있다 |
| 5 | 완료 항목을 체크하며 진행률을 확인한다 |
| 6 | 해결되지 않는 사항은 담당자 연결 경로로 문의한다 |
| 결과 | 담당자에게 도달하는 반복 문의가 감소한다 |

### UC-4. 후임 담당자가 과거 처리 기준을 파악한다 (Phase 1부터)

| 단계 | 내용 |
|---|---|
| 상황 | 인사발령으로 국외 HR 업무를 새로 맡았다 |
| 1 | 국가·유형·기간으로 과거 처리 건을 검색한다 |
| 2 | `질문 → 적용 조항 → 답변 → 확정일`이 연결된 형태로 조회된다 |
| 3 | 예외적으로 처리된 건은 사유가 함께 표시된다 |
| 결과 | 전임자에게 문의하지 않고 일관된 기준으로 처리한다 |

> ⚠️ **콘텐츠 정비가 이 프로젝트의 임계 경로다.** 규정은 자동 수집되나 안내서·양식·사례는 담당자가 정비해야 한다. **자료 수집은 사람이 아니라 산출물 기준으로 관리하고, 마감을 다음 정기인사 이전으로 설정한다.**

# VI. 성공 측정

## 19. 성공 지표 (KPIs) / Success Metrics

지표를 **성과 · 품질 · 채택** 세 축으로 나눈다. 사용자 수가 적어 통계적 A/B 검증이 어려우므로 **전후 비교와 골든셋 측정**을 병행한다.

### A. 성과 지표 — 업무가 실제로 줄었는가

| 지표 | 현재 | 목표 | 측정 방법 |
|---|---|---|---|
| 담당자 수신 문의 건수 (월) | 미측정 | baseline 대비 **40% 감소** | 문의 채널 로그 집계 |
| 셀프서비스 해결률 | 0% | **60%** | 담당자 개입 없이 종결된 세션 비율 |
| 2월 피크 문의 건수 | 미측정 | 전년 대비 **40% 감소** | 2월 한 달 문의 건수 |
| 문의 1건당 담당자 소요시간 | 미측정 | baseline 대비 **30% 단축** | 담당자 주 1회 기록 |

### B. 품질 지표 — 답이 맞는가 ⭐

| 지표 | 목표 | 측정 방법 |
|---|---|---|
| **골든셋 정답률** | **90% 이상** | 규정 100문항. 배포 전 + 이후 **분기별** 측정 |
| **출처 정확도** | **95% 이상** | 인용 조항이 실제 근거 조항과 일치하는 비율 |
| **L3 차단 재현율** | **95% 이상** | 유권해석 문항 20개 중 올바르게 차단한 비율 |
| **담당자 수정률** (edit rate) | **20% 이하** | AI 답변 대비 확정본의 변경 비율 (자동 집계) |
| **환각 건수** | **0건** | 월 1회 답변 로그 50건 무작위 감사 |

> **B는 사용자 수와 무관하게 측정 가능하므로, 사용자가 적은 초기에 신뢰할 수 있는 유일한 정량 근거다.**

### C. 채택 지표 — 실제로 쓰는가

| 지표 | 목표 | 측정 방법 |
|---|---|---|
| 담당자 주간 활성일 | **주 3일 이상** | 사용 로그 |
| 국외근무직원 월 활성 사용자 (Phase 2) | 129명 중 **30% 이상** | 사용 로그 |
| 재문의율 | **20% 이하** | 동일 사용자가 동일 주제로 7일 내 재질문한 비율 |

> Phase 0에서 2주간 baseline을 측정한 뒤 목표치를 확정한다. **기준선 없이 세운 목표는 성과를 증명하지 못한다.**

| **R4** | **L1+L2 비율이 낮아 효과가 작다** | 높음 | 중간 | **Phase 0에서 문의 30건 분류로 사전 검증.** 60% 미만이면 범위 재검토 또는 중단 |
| **R5** | **지식베이스 갱신 담당자가 인사발령으로 사라진다** | 높음 | **높음** | 규정은 자동 동기화로 사람 의존 제거. 안내서는 **역할 기준으로 담당 지정** |
| **R6** | **국외근무직원이 사용하지 않는다** (Phase 2) | 중간 | 중간 | Phase 1을 담당자 전용으로 운영해 품질 검증 후 공개. 사내 AI 플랫폼 내 배포로 접근 마찰 최소화 |
| **R7** | **AI가 근거 없는 답변을 생성한다** | **매우 높음** | 낮음 | 출처 강제 표기, 근거 미발견 시 "찾지 못했습니다" 응답, 월 1회 로그 감사 |
| **R8** | **자회사와 지점의 규정 차이를 혼동한다** | 중간 | 중간 | 국가·법인격을 데이터 모델 1급 차원으로 설계. 조건 미지정 시 되묻기 (FR-04) |
| **R9** | **효과 증명이 어렵다** (사용자 수가 적어 통계적 유의성 확보 곤란) | 중간 | **높음** | **골든셋 기반 품질 지표**를 주 근거로 사용. 사용자 수와 무관하게 측정 가능 |

# VIII. 범위

## 22. 제외 범위 / Out of Scope

| # | 제외 항목 | 사유 |
|---|---|---|
| 1 | **개인정보 처리** (급여액·가족·주소·여권) | 컴플라이언스 부담이 크게 달라진다. "규정상 이러한 기준으로 계산됩니다"까지만 안내하고 **개인별 실제 금액은 조회하지 않는다** |
| 2 | **급여시스템 연동** | 개인정보 처리를 전제로 하므로 함께 제외한다 |
| 3 | **규정 유권해석** | HR/직원만족부 소관이다. AI는 수행하지 않고 연결만 한다 |
| 4 | **사택 임차계약서 검토 및 품의문 작성** | 별도 검토 대상. Phase 1~2의 사례 축적 이후 추진이 유리하다 |
| 5 | **국외출장 관리** | 향후 검토. 여비규정 Q&A는 지식베이스 확장만으로 저비용 추가가 가능하다 |
| 6 | **항공·숙박 예약 시스템 연동** | 외부 시스템 연동으로 별도 프로젝트 규모다 |
| 7 | **국외근무직원 직접 공개 (Phase 1)** | Phase 1은 담당자 전용. 검증된 답변만 Phase 2에서 공개한다 |
| 8 | **담당자 확정 없는 답변 공개** | 어떤 답변도 사람의 확정 없이 공개되지 않는다 |

## 24. 일정 / Timeline

정확한 날짜 대신 단계로 관리한다. **각 단계는 이전 단계의 출시 기준(§20)을 충족해야 진행한다.**

| 단계 | 기간 | 주요 활동 | 산출물 |
|---|---|---|---|
| **Phase 0** 검증 | 2~4주 | 문의 30건 분류, 골든셋 작성, HR 협의, 자동 수집 확인, 안내서 1개국 확보 | L1+L2 비율, 골든셋 100문항, 협의 결과 |
| **Phase 1** MVP | — | 규정 Q&A (담당자 전용) 구축·운영. 안내서 정비 병행 | F1~F4, 사례 DB |
| **Phase 2** 확대 | — | 부임·복귀 체크리스트, 양식 제공, 국외근무직원 공개 | F5~F8 |
| **향후** | — | 출장 Q&A, 계약서 지원 등 확장 검토 | — |

**주요 마일스톤**
- M1: Phase 0 통과 판정 (L1+L2 60% 이상 확인)
- M2: Phase 1 출시 기준 충족 (골든셋 정답률 90%)
- M3: Phase 2 전환 기준 충족 (담당자 주 3일 사용, 수정률 20% 이하)
