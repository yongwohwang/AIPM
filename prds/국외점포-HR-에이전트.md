# 국외근무직원 HR 에이전트 PRD

## 한 장 요약

**무엇을** — 국외근무직원의 **부임·복귀 안내**와 **보수·복지 및 HR 규정 문의**에 답하는 AI 에이전트. 사내 AI 플랫폼 위에 구축한다.

**왜 지금** — ① 매년 2월 정기인사 시기에 부임·복귀 문의가 폭주하는데, 하필 그때 담당자도 교체된다 ② 규정 해석 노하우가 담당자 개인에게만 있어 인사발령마다 리셋된다 ③ 사내 규정 자동 수집 체계가 갖춰져 최신 규정 유지가 처음으로 가능해졌다.

**대상** — 1차는 본부 담당자 4~6명(내부 도구), 2차는 국외근무직원 129명(인니 16 · 캄보디아 8 · 국외점포 105).

| 하는 것 | 하지 않는 것 |
|---|---|
| 규정 조항 **원문 + 소관부서** 검색 | 규정 **유권해석** (HR/직원만족부 소관) |
| 부임·복귀 절차·서류·일정 안내 | **개인 급여액·가족·주소** 등 개인정보 처리 |
| 담당자 확정 답변의 사례 축적 | 급여시스템 연동 |
| 확정된 답변만 주재원에게 공개 | **사택 계약서 검토·품의문 작성** (향후 별도 검토) |

**단계** — Phase 0 검증(2~4주) → Phase 1 담당자 전용 규정 Q&A → Phase 2 부임·복귀 안내 + 주재원 공개

**핵심 설계** — AI는 **규정 원문 인용(L1)과 실무 안내(L2)만** 답하고, **유권해석(L3)은 답하지 않고 소관부서로 연결**한다. 이로써 소관(HR)과 답변 주체(글로벌)가 다른 문제를 구조적으로 해소한다.

**성공 판단** — 담당자 수신 문의 건수 감소, 셀프서비스 해결률, 골든셋 정답률. **Phase 0에서 baseline을 측정한 뒤 목표치를 확정한다.**

**지금 필요한 결정** — ① 자료 수집(부임 안내서·국가별 HR 사례) 마감을 다음 정기인사 이전으로 확정 ② HR/직원만족부 사전 협의 ③ 지식베이스 안내서 갱신 담당을 역할 기준으로 지정

## 1. Executive Summary

국외근무직원의 부임·복귀 절차 문의와 보수·복지·HR 규정 문의는 현재 본부 담당자가 개별적으로 응대한다. 같은 질문이 반복되고, 국가별 안내 자료의 형식이 제각각이며, 규정 해석은 담당자 개인의 경험에 의존한다.

이 프로젝트는 사내 AI 플랫폼 위에 **국외근무직원 HR 에이전트**를 구축해, 규정을 조항 원문과 소관부서까지 정확히 찾아주고 국가별 부임·복귀 절차를 안내한다. 1차 버전은 **담당자 전용 내부 도구**로 출시해 답변 품질을 실사용으로 교정한 뒤, **검증된 답변만** 국외근무직원에게 단계적으로 공개한다.

목표는 담당자의 반복 응대 부담을 줄이는 것을 넘어, **처리 근거를 시스템에 남겨 담당자가 교체되어도 업무 연속성이 유지되게** 하는 것이다.

## 2. Background & Context

### 2.1 현재 상태 (AS-IS)

- 국외근무직원이 부임 준비·보수·복지 관련 사항을 **담당자에게 직접 문의**한다 (메신저·메일·유선).
- 담당자가 규정집과 안내 자료를 찾아 개별 회신한다.
- 답변은 기록되지 않으므로 **같은 질문이 반복 발생**한다.
- 국가별 부임 안내 자료의 **형식이 통일되어 있지 않다**.
- 규정 해석 노하우와 과거 사례가 **담당자 개인의 암묵지**로만 존재한다.

### 2.2 조직 및 대상 규모

| 부서 | 관리 대상 | 성격 | 인원 |
|---|---|---|---|
| 글로벌성장지원부 | 국외 지분투자 자회사 | Inorganic | 인니 16 · 캄보디아 8 |
| 글로벌추진부 | 국외점포 · 현지법인 | Organic | 105 |
| | | **합계** | **129명** |

본부 담당자는 양 부서 합산 4~6명이다. 두 부서는 관리 대상의 **법인격이 다르므로**(자회사 vs 지점) 적용 규정이 다르다. **국가와 법인격을 데이터 모델의 1급 차원으로 설계**한다.

### 2.3 왜 지금인가

**① 2월에 모든 것이 겹친다**

정기인사발령이 있는 2월에 부임·복귀가 집중된다. 부임자들이 동시에, 대부분 **같은 질문**을 한다. 그런데 **2월은 담당자 본인도 교체되는 달이다.**

> **매년 2월마다, 가장 경험이 적은 담당자가 가장 많은 문의를 받는다.**

**② 암묵지가 인사발령마다 리셋된다**

담당자 작성 자료에 *"담당자 경험 및 노하우(암묵지) 의존"* 이 문제점으로 명시되어 있고, 자료 하단에는 *"인사발령에 따라 업무별 담당자 변동 가능"* 이라고 적혀 있다. 순환보직 구조에서 1~2년마다 지식이 사라진다.

**③ 규정 최신성 유지가 처음으로 가능해졌다**

사내 **규정 자동 수집 시스템**이 이미 존재한다. 과거에는 규정을 수동 관리해야 해서 최신성 유지가 불가능했다. 이것이 지금 시작할 수 있게 된 결정적 변화다.

## 3. Objectives & Success Metrics

### 3.1 Objective

> **국외근무직원이 부임·복귀 절차와 보수·복지 규정을 담당자에게 묻지 않고 스스로 확인할 수 있게 하고,
> 담당자의 답변 근거(규정 조항·소관부서·과거 사례)를 100% 시스템에 기록해
> 담당자 교체와 무관하게 일관된 답변이 유지되게 한다.**

### 3.2 Goals

1. 담당자가 규정을 찾을 때 **조항 원문과 소관부서까지** 한 번에 확인할 수 있게 한다.
2. 국외근무직원이 **국가·법인격에 맞는** 부임·복귀 절차와 제출 서류를 스스로 확인할 수 있게 한다.
3. 담당자가 확정한 답변을 **사례로 축적**해 담당자 교체 후에도 조회 가능하게 한다.
4. 규정 **유권해석이 필요한 질문은 AI가 답하지 않고** 소관부서로 연결한다.
5. 2월 피크 시 담당자에게 도달하는 **반복 문의를 줄인다**.

### 3.3 Non-Goals

1. **개인정보 처리** — 급여액·가족 정보·주소·여권 등을 처리하지 않는다. "규정상 이러한 기준으로 계산됩니다"까지만 안내하고 **개인별 실제 금액은 조회하지 않는다.**
2. **급여시스템 연동** — 범위 밖.
3. **규정 유권해석** — HR/직원만족부 소관이며 AI는 수행하지 않는다.
4. **사택 임차계약서 검토 및 품의문 작성** — 향후 별도 검토. 본 범위에 포함하지 않는다.
5. **국외출장 관리** — 향후 검토. 여비규정 Q&A는 Phase 2 이후 저비용으로 추가 가능.
6. **국외근무직원 직접 공개(1차)** — Phase 1은 담당자 전용. 검증된 답변만 Phase 2에서 공개한다.
7. **담당자 승인 없는 답변 공개** — 어떤 답변도 담당자 확정 없이 대외 공개되지 않는다.

### 왜 담당자가 먼저인가

국외근무직원 대상 챗봇을 먼저 만들 경우의 리스크는 기술이 아니라 **채택**이다. 급하면 챗봇 대신 담당자에게 메신저를 보낸다. 더 빠르고, 확실하고, 책임 소재가 명확하기 때문이다. 부임은 2~3년에 1회 발생하는 이벤트라 재방문이 없어 학습 곡선도 타지 못한다.

담당자를 먼저 대상으로 하면 **채택이 보장되고**(어차피 규정을 찾아야 한다), **답변 품질을 실사용으로 교정**할 수 있으며(담당자가 오답을 즉시 잡아낸다), **공개 시점에 이미 검증된 상태**가 된다. 담당자가 대체 대상이 아니라 소유자가 되므로 조직 내 저항도 없다.

## 5. Solution

### 5.1 핵심 설계 — 답변 책임 등급 (L1 / L2 / L3)

국외근무 지침의 소관은 **HR/직원만족부**이나 실무 답변은 **글로벌사업그룹**이 수행한다. 이 분업 자체는 정상이지만, AI 시스템에 넣으면 **기록이 남고, 129명에게 동시에 전달되며, "부서 공식 견해"로 인식된다.** 지금까지 "담당자의 실무 안내"였던 것이 "부서의 유권해석"처럼 보이게 된다.

모든 답변을 세 등급으로 구분하고 **AI는 L1·L2만 수행한다.**

| 등급 | 유형 | 예시 | 소관 | AI |
|---|---|---|---|---|
| **L1** | 규정 원문 인용 | "보수·복지 규정 제○조: 주택수당 한도는 ○○" | HR 소관이나 **인용은 해석이 아님** | ✅ |
| **L2** | 절차·실무 안내 | "부임 전 제출 서류는 ○○이며 양식은 여기 있습니다" | **글로벌 자체 소관** | ✅ |
| **L3** | 해석·판단 | "배우자가 현지 취업했는데 가족수당 대상인가요?" / "예외 승인 가능한가요?" | **HR 유권해석 필요** | ❌ 차단 |

> **현재 담당자가 하는 답변의 대부분은 이미 L1 + L2다.** 진짜 유권해석이 필요한 L3는 현재도 HR에 확인하고 있다.
> 따라서 **AI는 책임 경계를 바꾸지 않는다. 암묵적으로 지켜지던 경계를 명시적으로 만들 뿐이다.**
> 오히려 현재보다 안전하다 — 지금은 담당자가 무심코 L3를 답할 수 있지만, 시스템은 이를 감지해 차단한다.

**부수 효과**: L3 질문의 대부분이 "제 경우에는?" 형태다. **개인정보를 처리하지 않기로 한 결정(Non-Goal 1)이 자연스럽게 L3를 차단하는 방어 장치로 작동한다.**

### 5.3 Technology

**아키텍처**

```
규정·지침 ──(자동 동기화)──┐
부임 안내서 ──(부서 관리)──┼──▶ 문서 파이프라인 ──▶ [지식베이스]
서류 양식  ──(부서 관리)──┤   파싱→청킹→메타데이터    + 버전 / 시행일
과거 사례  ──(자동 축적)──┘   (시행일·국가·법인격·소관)
                                                    │
                        ┌───────────────────────────▼──────────┐
                        │      HR 에이전트 (사내 AI 플랫폼)     │
                        │  Guard: classify(q) → L1 / L2 / L3   │
                        │  Tools:                              │
                        │   • search_regulation(q, country)    │
                        │   • get_checklist(country, type)     │
                        │   • get_form(country, purpose)       │
                        │   • log_case(...)                    │
                        └───────────────┬──────────────────────┘
                                        │
              ┌─────────────────────────┼─────────────────────┐
              ▼                         ▼                     ▼
      [답변 + 출처 + 소관]      [부임 체크리스트]      [L3 → 소관부서 연결]
              │
              └──▶ 🚦 담당자 확정 ──▶ 사례 DB ──▶ 지식베이스 재투입 (교정 루프)
                                          │
                                          └──▶ 공개 전환 (Phase 2)
```

**설계 원칙**

| # | 원칙 | 이유 |
|---|---|---|
| 1 | 에이전트는 **제안**만, **확정**은 사람이 | 책임 경계. 컴플라이언스 통과의 전제 |
| 2 | **툴 목록 자체가 하드 가드레일** | 프롬프트로 통제하지 않는다. 툴에 없는 일은 할 수 없다 |
| 3 | 모든 답변에 **출처 + 소관** 필수 | 은행에서 출처 없는 답변은 신뢰받지 못한다 |
| 4 | **"모른다"고 말하는 것이 기능** | 틀린 답 1건이 맞는 답 100건의 신뢰를 없앤다 |
| 5 | 규정 문서에 **시행일·버전·소관 메타데이터 필수** | 없는 문서는 인덱싱하지 않는다 |
| 6 | **국가·법인격은 1급 차원** | 자회사와 지점은 적용 규정이 다르다 |
| 7 | 챗봇은 기능이 아니라 **플랫폼** | 향후 계약서·출장 기능은 툴 추가로 확장 |

**지식베이스 운영**

| 구분 | 관리 방식 | 소유 |
|---|---|---|
| 규정·지침 | **자동 동기화** (사내 규정 수집 시스템) | 시스템 |
| 부임 안내서 · 서류 양식 | 수동 등록·갱신 | 글로벌성장지원부 / 글로벌추진부 |
| 사례 | 담당자 확정 시 자동 축적 | 시스템 |

## 6. Release Plan

날짜 대신 단계로 표기한다. **각 단계는 이전 단계의 성공 기준을 충족해야 다음으로 넘어간다.**

### Phase 0 — 검증 (개발 착수 전, 2~4주)

계약서 기능을 범위에서 제외하면서 **정량 근거가 문의량 측정에 전적으로 의존**하게 되었다. 이 단계는 생략할 수 없다.

- [ ] ⭐ **담당자 수신 문의 baseline 2주 측정** — 건수, 유형, 건당 소요시간
- [ ] 문의 100건을 **L1 / L2 / L3로 분류** → L1+L2 비율 산출 (A1)
- [ ] **2월 문의 집중도** 확인 — 전년 2월 vs 평월 비교
- [ ] **규정 골든셋 100문항 작성** (질문 + 정답 + 근거 조항) → 품질 측정 기준선
- [ ] **L3 문항 20개** 별도 작성 → 차단 정확도 측정용
- [ ] 규정 자동 수집 **세부 확인** — 개정 반영 주기 / 메타데이터 / 폐지 규정 제외
- [ ] **규정별 소관부서 목록** 작성 (HR 소관 vs 자체 소관)
- [ ] ⭐ **HR/직원만족부 사전 공유** — L1 인용 범위 확인, 답변 검수 협조 요청
- [ ] **부임 안내서 1개국분을 2주 내 실제 확보** (일정 현실성 검증)

**진행 기준**: L1+L2 답변 가능 비율 **60% 이상** + 자료 수집 일정이 현실적일 것.

### Phase 1 — 담당자 전용 규정 Q&A

**대상**: 본부 담당자 4~6명 / **범위**: 보수·복지·인사 규정 (국가 공통 규정 우선)

| 기능 | 내용 |
|---|---|
| 규정 Q&A | 조항 원문 + 소관부서 표기, L1·L2만 응답 |
| L3 차단 | 유권해석 질문 감지 → 소관부서 연결 |
| 사례 축적 | 담당자 확정본 자동 기록 |
| 교정 루프 | 확정본이 지식베이스로 재투입 |

**🎯 성공 기준**: 골든셋 정답률 90% 이상 + 담당자 주 3일 이상 자발적 사용 + 수정률 20% 이하

> 보수·복지 규정을 먼저 하는 이유: **규정은 자동 수집되므로 자료 준비가 필요 없다.** 부임 안내서는 국가별 정비가 선행되어야 하므로 Phase 2로 둔다.

### Phase 2 — 부임·복귀 안내 + 국외근무직원 공개

- 국가별 **부임·복귀 개인화 체크리스트** (Phase 1 기간에 안내서 정비 병행)
- **제출 서류 양식** 직접 제공
- 담당자가 **확정한 답변만** 국외근무직원에게 공개
- 파일럿 1개국(인도네시아 우선) → 순차 확대

**🎯 성공 기준**: 담당자 수신 문의 40% 감소 + 셀프서비스 해결률 60% + 재문의율 20% 이하

### 향후 검토 (범위 밖)

| 항목 | 비고 |
|---|---|
| 국외출장 Q&A · 출장비 계산 | 여비규정을 지식베이스에 추가하면 저비용으로 확장 가능 |
