## 1. Executive Summary

국외근무직원(주재원)의 사택 임차계약 검토와 품의문 작성, 그리고 보수·복지·부임 관련 규정 문의 응대는 현재 본부 담당자가 100% 수작업으로 처리하고 있다. 이 프로젝트는 사내 AI 플랫폼 위에 **국외근무직원 HR 에이전트**를 구축해, 규정을 조항 원문과 소관부서까지 정확히 찾아주고, 계약서 작성 가이드를 현지에 직접 제공하며, 사택 임차계약 품의문 초안을 자동 생성한다.

목표는 담당자의 작업 시간을 줄이는 것을 넘어, **현지가 스스로 완결된 문서를 제출하게 만들어** 매년 2월 정기인사발령 시기에 집중되는 병목을 해소하고, 처리 근거를 시스템에 남겨 담당자가 교체되어도 업무 연속성이 유지되게 하는 것이다.

1차 버전은 **담당자 전용 내부 도구**로 출시하며, 검증된 답변만 주재원에게 단계적으로 공개한다.

## 3. Background & Context

### 3.1 현재 프로세스 (AS-IS)

```
① 주재원이 계약서 송부 → ② 담당자가 계약 내용 검토 → ③ 계약정보 수기 입력(엑셀)
→ ④ 규정 적합 여부 확인 → ⑤ 품의문 작성 → ⑥ 승인 및 발송
```

이 과정 전체를 담당자 1인이 수행하며, **건당 약 2시간**이 소요된다.

### 3.2 실측 데이터

| 항목 | 값 |
|---|---|
| 사택 임차계약 건수 | **2년간 32건 = 연 16건** (인도네시아·캄보디아, 신규 + 연장) |
| 발생 시기 | **매년 2월 정기인사발령 시 집중** |
| 건당 담당자 소요시간 | **2시간** (계약서 검토 + 품의문 작성) |
| 현재원 | 인도네시아 16명 · 캄보디아 8명 · 국외점포 105명 (**총 129명**) |
| 본부 담당자 | 4~6명 (양 부서 합산) |

### 3.3 왜 지금인가 — 세 가지 이유

**① 2월에 모든 것이 겹친다** ⭐

연 16건은 고르게 발생하지 않는다. 정기인사발령이 있는 2월에 집중된다. 그런데 **2월은 담당자 본인도 교체되는 달이다.**

> **매년 2월마다, 가장 경험이 적은 사람이 가장 많은 건을, 부임 업무까지 폭주하는 시기에 처리하게 된다.**

연 32시간이라는 총량은 크지 않다. 문제는 총량이 아니라 **피크와 인수인계 공백이 정확히 같은 시점에 발생한다**는 구조다.

**② 장부에 잡히지 않는 왕복 비용이 있다**

담당자 진술:
> *"현지에서 계속 문의가 올 거야. 이거 어떻게 작성하면 돼요, 이 초안은 괜찮나요…"*

건당 2~3회의 왕복 문의가 발생하며, 여기에는 담당자 시간뿐 아니라 현지 직원의 시간과 대기 리드타임이 함께 든다. **실제 비용은 기록된 2시간보다 크다.**

**③ 암묵지가 인사발령마다 리셋된다**

현재 규정 해석 노하우와 과거 처리 사례는 담당자 개인의 경험에 의존한다. 순환보직으로 1~2년마다 담당자가 바뀌면 그 지식이 사라진다. 담당자 작성 자료에도 *"담당자 경험 및 노하우(암묵지) 의존"* 이 문제점으로 명시되어 있다.

### 3.4 무엇이 새로 가능해졌나

| 조건 | 상태 |
|---|---|
| 사내 AI 플랫폼 (RAG · 파일 업로드 · 툴 호출) | ✅ 전부 지원, 구축 가능 |
| 사내 규정 자동 수집 시스템 | ✅ 이미 존재 |

과거에는 규정을 수동으로 관리해야 해서 최신성 유지가 불가능했으나, **규정 자동 수집 체계가 갖춰져 사람 의존 없이 최신 규정을 유지할 수 있게 되었다.** 이것이 이 프로젝트를 지금 시작할 수 있게 만든 결정적 변화다.

### 3.5 조직 맥락

| 부서 | 관리 대상 | 성격 | 대상 인원 |
|---|---|---|---|
| 글로벌성장지원부 | 국외 지분투자 자회사 | Inorganic | 인니 16 · 캄보디아 8 |
| 글로벌추진부 | 국외점포 · 현지법인 | Organic | 105 |

두 부서는 관리 대상의 **법인격이 다르다**(자회사 vs 지점). 적용 규정·계약 주체·세무 체계가 다르므로, **국가와 법인격을 데이터 모델의 1급 차원으로 설계**한다. 1차 범위는 자회사 라인(인니·캄보디아)으로 통일해 규정 매칭을 단순화한다.

## 4. Objectives & Success Metrics

### 4.1 Objective

> **현지가 스스로 완결된 계약·품의 문서를 제출하게 만들어 2월 피크의 담당자 병목을 해소하고,
> 처리 근거(규정 조항·소관부서·과거 사례)를 100% 시스템에 기록해 담당자 교체와 무관하게 업무가 재현 가능하게 한다.**

이는 **"담당자의 2시간을 1시간으로 줄이는 자동화"가 아니라 "현지가 스스로 해결하게 만드는 셀프서비스 전환"** 이다. 목표 설정과 지표가 여기서 갈린다.

### 4.2 Goals

1. 담당자가 규정을 찾을 때 **조항 원문과 소관부서까지** 한 번에 확인할 수 있게 한다.
2. 현지가 계약서를 **처음부터 올바르게** 작성할 수 있도록 표준 양식과 작성 가이드를 직접 제공한다.
3. 사택 임차계약 품의문을 **초안 상태로 자동 생성**해, 담당자가 작성자가 아닌 검토자가 되게 한다.
4. 담당자가 확정한 답변과 처리 근거를 **사례로 축적**해 담당자 교체 시에도 조회 가능하게 한다.
5. 규정 **유권해석이 필요한 질문은 AI가 답하지 않고** 소관부서로 연결한다.

### 4.3 Non-Goals

1. **개인정보 처리** — 급여액·가족 정보·주소·여권 등을 처리하지 않는다. "규정상 이러한 기준으로 계산됩니다"까지만 안내하고 개인별 실제 금액은 조회하지 않는다.
2. **급여시스템 연동** — 1차 범위 밖.
3. **규정 적합/부적합 판정** — AI는 계약 조건이 규정에 맞는지 **판정하지 않는다.** 조건 추출과 체크리스트 표시까지만 하고 판단은 담당자가 한다.
4. **규정 유권해석** — HR/직원만족부 소관이며 AI는 수행하지 않는다.
5. **주재원 직접 공개** — 1차는 담당자 전용. 검증된 답변만 Phase 2에서 단계적으로 공개한다.
6. **국외출장 관리** — Phase 2로 이연. 항공·숙박 예약 시스템 연동은 별도 프로젝트로 분리한다.
7. **비영어권 현지어 원본 처리** — 현재 계약서는 한국어 품의 + 영문 계약서로 도달하므로 범위 밖.
8. **담당자 승인 없는 문서 확정** — 어떤 산출물도 사람의 승인 없이 확정되지 않는다.

### 4.4 Success Metrics

| Metric | Current | Target | Measurement |
|---|---|---|---|
| **현지 제출본 1차 통과율** (핵심) | 미측정 — Phase 0에서 baseline 확보 | baseline 대비 **+30%p** | 담당자 반려·재문의 없이 통과한 건 / 전체 접수 건 |
| **계약 1건당 현지 왕복 문의 횟수** | 미측정 | baseline 대비 **50% 감소** | 건별 문의 스레드 수 집계 |
| **2월 피크 리드타임** (접수 → 품의문 완료) | 미측정 | baseline 대비 **50% 단축** | 접수 시각 ~ 담당자 승인 시각 로그 |
| 담당자 건당 소요시간 | **2시간** | 1시간 이하 | 담당자 자기보고 + 시스템 로그 |
| 근거 조항·소관부서 자동 기록률 | 0% | **100%** | 처리 건 로그 감사 |
| 담당자 승인 없이 확정된 산출물 | 0건 | **0건 유지** | 승인 로그 감사 |
| L3(유권해석) 질문에 AI가 답변한 건수 | — | **0건** | 답변 로그 샘플 감사 (월 1회) |
| 담당자가 자발적으로 사용한 주간 활성일 | — | 주 3일 이상 | 사용 로그 |

> Phase 0에서 2주간 baseline을 측정한 뒤 목표치를 확정한다. 측정 기준선 없이 목표를 세우면 성과를 증명할 수 없다.

## 5. Target Users & Segments

시장은 인구통계가 아니라 **사람들이 하려는 일(job)** 로 정의한다.

| 세그먼트 | 규모 | 사용 빈도 | 하려는 일 | Phase |
|---|---|---|---|---|
| **A. 본부 담당자 (HR·계약)** | 4~6명 | **매일** | 계약서 검토, 품의문 작성, 규정 문의 응대, 데이터 관리 | **Phase 1 (주 사용자)** |
| **B. 현지 직원 / RM** | 인니 16 · 캄보디아 8 | 계약 시점 집중 | 계약서를 올바르게 작성해 한 번에 통과시키기 | **Phase 1 (간접) → Phase 2 (직접)** |
| C. 주재원 (부임 준비 중) | 연간 수십 명 | 생애 1~2회 | 부임 준비 항목 파악 | Phase 2 |
| D. 주재원 (근무 중) | 129명 | 산발적 | 보수·복지 규정이 내 상황에 어떻게 적용되는지 확인 | Phase 2 |
| E. 후임 담당자 | 1~2년마다 교체 | 인수인계 시점 | 전임자의 판단 근거와 과거 사례 파악 | Phase 1부터 자동 축적 |

### 왜 담당자가 먼저인가

주재원 챗봇을 먼저 만들 경우의 리스크는 기술이 아니라 **채택**이다. 주재원은 급하면 챗봇 대신 담당자에게 메신저를 보낸다. 더 빠르고, 확실하고, 책임 소재가 명확하기 때문이다. 부임은 1인당 2~3년에 1회 발생하는 이벤트라 재방문이 없어 학습 곡선도 타지 못한다.

담당자를 먼저 대상으로 하면:
- **채택이 보장된다** — 어차피 규정을 찾아야 하므로 조금이라도 빠르면 쓴다
- **답변 품질을 실사용으로 교정한다** — 담당자가 오답을 즉시 잡아내고, 그 교정본이 지식베이스가 된다
- **주재원 오픈 시점에 이미 검증된 상태다** — 챗봇 실패의 최대 원인(초기 품질 저하 → 신뢰 상실)을 원천 제거
- **조직 내 저항이 없다** — 담당자가 대체 대상이 아니라 소유자가 된다

### 제약 조건

- 국가와 법인격(자회사/지점)에 따라 적용 규정이 다르다 → 1차는 자회사 라인으로 통일
- 담당자는 인사발령으로 교체된다 → 개인이 아닌 시스템에 지식이 남아야 한다
- 규정 소관이 부서별로 혼재한다 → 답변 책임 범위를 명시적으로 제한해야 한다 (§7.2 L1/L2/L3)

## 6. Value Propositions

### 6.1 본부 담당자에게

| 현재의 고통 | 제공하는 가치 |
|---|---|
| 20페이지 영문 계약서를 처음부터 읽어야 함 | 핵심 조건이 추출되어 확인이 필요한 항목만 집중 |
| 품의문을 매번 처음부터 작성 | 초안이 채워진 상태로 도착 — **작성자가 아닌 검토자** |
| 현지에서 같은 질문이 반복 도착 | 현지가 가이드를 보고 스스로 해결 |
| 규정집을 뒤져 근거를 찾음 | 조항 원문 + 소관부서가 즉시 검색됨 |
| 2월에 모든 것이 몰림 | 피크 시 처리량이 시스템으로 흡수됨 |
| 인수인계 시 전임자에게 계속 물어봄 | 과거 처리 건이 근거와 함께 조회됨 |

### 6.2 현지 직원 / 주재원에게

| 현재의 고통 | 제공하는 가치 |
|---|---|
| 계약서를 어떻게 써야 할지 몰라 본부에 물어봄 | 표준 양식 + 작성 가이드 + 유의사항을 즉시 확인 |
| 제출 후 반려되어 다시 작업 | 제출 전에 필요한 항목을 미리 확인 |
| 답변을 기다리는 대기 시간 | 즉시 응답 |
| 규정 근거를 알 수 없어 납득이 안 됨 | 조항 원문이 함께 제시됨 |

### 6.3 경쟁 대안 대비

| 대안 | 한계 |
|---|---|
| 담당자에게 직접 문의 (현행) | 담당자 시간 소모, 2월 병목, 답변이 기록되지 않음 |
| 안내서 PDF 배포 | 국가별 형식 불일치, 개정 반영 지연, 검색 불가 |
| 범용 사내 AI에 질문 | 국외근무 규정·양식·사례를 모름. 출처와 소관 표기 없음 |
| **본 에이전트** | 규정 자동 동기화 + 출처·소관 표기 + 승인 게이트 + 사례 축적 |

## 7. Solution

### 7.1 사용자 흐름

**흐름 A — 규정 문의 (담당자)**
```
질문 입력 → 규정 검색 → [L3 판정] ─ L3면 ─→ 답변하지 않고 소관부서 연결
                              └ L1·L2면 ─→ 조항 원문 + 소관부서 + 면책문구 표시
                                              → 담당자 확정 → 사례로 축적
```

**흐름 B — 계약서 작성 지원 (현지 → 담당자)**
```
"인도네시아 사택 계약서 어떻게 쓰나요?"
  → 표준 양식 + 작성 가이드 + 유의사항 제공
  → 현지가 작성해 제출
  → 담당자가 검토 (반려 없이 통과되는 것이 목표)
```

**흐름 C — 품의문 초안 생성 (담당자)**
```
계약서 업로드 → 조건 추출 (원문 위치 하이라이트)
  → 담당자가 추출값 확인·수정
  → 품의문 초안(.docx) 자동 생성
  → 🚦 담당자 승인 게이트
  → 승인 후 확정 + 계약DB 적재 + 사례 축적
```

> **모든 흐름의 공통 원칙**: 에이전트는 **제안(propose)** 만 하고, **확정(commit)** 은 언제나 사람이 한다.

### 7.2 Key Features

#### 🔑 핵심 설계 — 답변 책임 등급 (L1 / L2 / L3)

국외근무 지침의 소관은 **HR/직원만족부**이나 실무 답변은 **글로벌사업그룹**이 수행한다. 이 분업 자체는 정상이지만, AI 시스템에 넣으면 **기록이 남고, 129명에게 동시에 전달되며, "부서 공식 견해"로 인식된다.** 지금까지 "담당자의 실무 안내"였던 것이 "부서의 유권해석"처럼 보이게 된다.

이를 해결하기 위해 모든 답변을 세 등급으로 구분하고 **AI는 L1·L2만 수행한다.**

| 등급 | 유형 | 예시 | 소관 | AI |
|---|---|---|---|---|
| **L1** | 규정 원문 인용 | "보수·복지 규정 제○조: 주택수당 한도는 ○○" | HR 소관이나 **인용은 해석이 아님** | ✅ |
| **L2** | 절차·실무 안내 | "계약서는 이 양식으로 담당자에게 제출" | **글로벌 자체 소관** | ✅ |
| **L3** | 해석·판단 | "배우자가 현지 취업했는데 가족수당 대상인가요?" / "이 조건이 규정 위반인가요?" / "예외 승인 가능한가요?" | **HR 유권해석 필요** | ❌ 차단 |

> **현재 담당자가 하는 답변의 대부분은 이미 L1 + L2다.** 진짜 유권해석이 필요한 L3는 현재도 HR에 확인하고 있다.
> 따라서 **AI는 책임 경계를 바꾸지 않는다. 암묵적으로 지켜지던 경계를 명시적으로 만들 뿐이다.**
> 오히려 현재보다 안전하다 — 지금은 담당자가 무심코 L3를 답할 수 있지만, 시스템은 이를 감지해 차단한다.

**부수 효과**: L3 질문의 대부분이 "제 경우에는?" 형태다. 개인정보를 처리하지 않기로 한 결정(Non-Goal 1)이 자연스럽게 L3를 차단하는 방어 장치로 작동한다.

| # | 원칙 | 이유 |

| 1 | 에이전트는 **제안**만, **확정**은 사람이 | 책임 경계. 컴플라이언스 통과의 전제 |

- [ ] ⭐ **HR/직원만족부 사전 공유** — L1 인용 범위 확인, 답변 품질 검수 협조 요청
- [ ] 자료 수집 4개 항목 중 **1개를 2주 내 실제 확보** (일정 현실성 검증)
- [ ] 규정 20문항 골든셋으로 사내 플랫폼 RAG 정확도 측정

**진행 기준**: L1+L2로 답변 가능한 문의 비율이 60% 이상이고, 자료 수집 일정이 현실적일 것.

### Phase 1 — Wedge (담당자 전용, 인도네시아 우선)

| 기능 | 내용 |
|---|---|
| **규정 Q&A** | 조항 원문 + 소관부서 표기, L1·L2만 응답 / L3 차단 |
| **계약서 양식·가이드 제공** | 툴 불필요. 왕복 문의를 직접 제거 |
| **품의문 초안 생성** | 사택 임차계약 품의문 1종 |
| **사례 축적 + 교정 루프** | 담당자 확정본이 지식베이스로 재투입 |

**🎯 성공 기준**: 담당자가 자발적으로 계속 사용한다 (주 3일 이상) + 2월 피크 리드타임 단축

> ⚠️ 품의문을 1종만 만들면 템플릿 구조가 일반화되었는지 검증되지 않는다. Phase 1 후반에 두 번째 종류(학자금 요청 품의문 등)를 추가해 하드코딩과 구분할 것을 권고한다.

### Phase 2 — 현지·주재원 오픈 + 확장

- 담당자가 **확정한 답변만** 현지·주재원에게 공개 (인니 16명 + 캄보디아 8명 먼저)
- 계약서 업로드 → **필드 추출** + 계약관리 DB 적재 (엑셀 수기 입력 대체)
- 부임·복귀 **개인화 체크리스트**
- **국외출장 Q&A + 출장비 계산기** — 여비규정을 지식베이스에 추가하면 대부분 따라온다

**🎯 성공 기준**: 현지 제출본 1차 통과율 상승, 건당 왕복 문의 횟수 감소

### Phase 3 — 본격 확장

- **규정 적합성 체크리스트** — Phase 1~2의 사례 축적 이후에야 정합성 확보 가능
- **지점 라인 확대** (런던·홍콩 등 / 글로벌추진부 / 105명) — 자회사와 규정 체계가 다르므로 규정 매핑 별도 검증. 계약 건수 기준 약 4배 규모
- 항공·숙박 **예약 시스템 연동** — 별도 프로젝트로 검토

### 확장 원칙

담당자 자료의 기능 4개(부임안내 / 보수복지 / 계약서 / 출장)를 **순서대로 하나씩** 만드는 것이 아니라, **각 기능을 난이도별로 쪼개어 쉬운 조각을 앞으로 당긴다.**

예: "계약서 관리"의 네 조각 중 **표준양식 제공·작성 가이드는 툴이 필요 없으므로 Phase 1에 포함**하고, 적합성 검토는 Phase 3로 미룬다. 출장 관리도 **Q&A와 계산기는 저비용으로 Phase 2에 붙고**, 예약 연동만 별도로 분리한다.
